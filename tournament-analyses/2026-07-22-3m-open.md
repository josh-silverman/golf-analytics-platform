## ⚠️ Critical finding first — read before using any number

**The live product is not serving what it claims to serve this week.** Traced end to end:

- DataGolf rates Scheffler to **win at 23.7%** (raw, sums correctly to 1.0 across the field). The **served board shows him at 2.24%** — a ~10× compression. The entire served win market spans only 0.6%–2.2%.
- Root cause is a code bug, not calibration: `CachingProviderWrapper` (the production provider) implements `get_pretournament_preds` but **not** `get_pretournament_full_preds` — the five-market method Path A serving depends on. With no override and no `__getattr__`, that call hits the base-class default returning `{}`. Its own docstring states the consequence: *"Path A cold-starts every player to the SG-only model on a provider that doesn't override this."*
- **Consequence:** every player silently falls back to the **v2 SG-only model**, whose win market is the known flat/collapsed one. Path A's DataGolf-direct serving is inert in production. The same collapse was confirmed on the prior week's live Open board (McIlroy served at 2.28%).

**Implication for this report:** the "served" numbers are the v2 model, and its **win output is unusable**. Win / value / top-20 / make-cut picks below are built from **DataGolf's raw probabilities** (what Path A intends to serve, readable via the unwrapped provider), with the served v2 values shown alongside to expose where the live board diverges. The bug was **not** fixed as part of this analysis — flagged for a separate task.

> Note: the forward out-of-sample track record grades these same served boards, so those skill numbers reflect the v2 model, not DataGolf-direct — real, but mislabeled "Path A" until this bug is fixed.

## Model Insights

1. **The serving bug is the story of the week** — the live board is the v2 SG model, not DataGolf; win is collapsed 10×. The leaderboard win column and betting-edge win rows are unreliable until `get_pretournament_full_preds` is forwarded through the caching wrapper.
2. **Scheffler is a historic mismatch for this field.** +2.78 projected SG where the 20th-best player is ~+0.4. DataGolf is even higher on him than the sharp market — the rare case where "fade the chalk" has no support.
3. **TPC Twin Cities course-fit is doing real work in the second tier.** DataGolf's decomposition surfaces fit as the driver for value names with unremarkable raw SG: **Ben Kohles (+0.25 fit)**, **Zac Blair (+0.27 fit)**, Christiaan Bezuidenhout (+0.16). **Doug Ghim's** edge is course *history* (+0.123, highest among contenders) — the one place the broken live model lands bullish for a defensible reason (served make-cut 86% vs DG 71%).
4. **Bombers are not being rewarded here.** Keith Mitchell (+10.2 driving dist), Kitayama (+9.5), Knapp (+12.6) are among the field's longest, yet DataGolf's driving-distance adjustment is **negative** for all three (−0.099, −0.092, −0.06). The model reads the course as one where distance doesn't convert — a genuine anti-narrative signal.
5. **Where the model agrees with consensus:** the top of the board — DataGolf and the sharp market rank the same 5–6 names in the same order across every market. Disagreement concentrates in the 15–40% top-20 band, which is exactly where edges are findable.

## Methodology Notes

- **What the model evaluates:** five nested markets (win ⊆ top-5 ⊆ top-10 ⊆ top-20 ⊆ make-cut), each a probability, forced coherent (running-max) and field-normalized (win → 1, top-5 → 5, …). Underlying signal is strokes-gained: per-category skill (off-tee / approach / around-green / putting), field-relative margins, recent-form index, round-to-round volatility.
- **Intended vs actual source:** Path A is designed to serve DataGolf's `baseline_history_fit` directly to covered players (all 144 here) and use the v2 SG model only for cold-starts. Due to the bug above, actual serving = v2 model for everyone. DataGolf's own model exposes feature contributions via its decomposition (course history, course fit, driving distance / accuracy, age, timing); the v2 model's contributions are its SG-category and field-relative features.
- **Market comparison:** sportsbook consensus (DataGolf's own baseline excluded), de-vigged by scaling each market to its true field total, so edge = model prob − fair implied.
- **Confidence metrics available but not tabled:** DataGolf `std_deviation` + `sample_size` per player; the v2 model's `round_count` + `score_volatility`.
